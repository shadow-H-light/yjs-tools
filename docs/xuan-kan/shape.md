# 选刊神器 · 产品形态

对应决策 D3（方案 B）和 D4（本地小工具，可做插件）。

## 一句话

不是网站，也不是大后台。是一台电脑上能跑起来的选刊工具：核心是本机 FastAPI，界面和插件都只是它的客户端。

## 怎么用

```text
本机数据（SQLite + 导入的 CSV）
        ↑
   FastAPI（只监听 127.0.0.1）
        ↑
   ┌────┴────┐
本地网页控制台   以后的插件（Zotero / 浏览器）
```

1. 安装 Python 环境，一条命令启动。
2. 浏览器打开 `http://127.0.0.1:8765` 做检索、导入、对比。
3. 需要时再装插件：在 Zotero 或期刊网页里点一下，请求打到同一个本机服务。

默认不注册账号、不上云、不把期刊库放到别人的服务器。

## 体积怎么压住

| 要 | 不要 |
| --- | --- |
| 单机、单用户、单端口 | 多租户、登录系统、云同步 |
| SQLite 一个文件 | 默认上 PostgreSQL / Docker 集群 |
| FastAPI 一个进程（生产时带上构建好的前端） | Next.js、Vercel、独立前端主机 |
| 用户自己点「同步 OpenAlex」「导入 CSV」 | 常驻爬虫、后台调度平台 |
| 插件只调本机 API | 插件里内置一份期刊库 |

向量检索用 SQLite 扩展（如 `sqlite-vec`）或先做「主题重合、不上向量」。embedding 模型可选、可关：没装模型时，关键词只走刊名和 Topic 映射。

## 插件放哪一期

v0.1 先交付本机服务 + 本地网页。插件是同一套 API 的第二个壳，不另做业务。

优先考虑的插件形态（二期选一个）：

- **Zotero**：在条目上查期刊分区/匹配，和文献工作流最近。
- **浏览器扩展**：在出版社主页看到本机库里的分区和匹配分。

插件不代替本机服务。没启动本地进程时，插件应提示「请先启动选刊神器」，而不是自己去抓网。

## 和其他 yjs-tools 模块

导师、学校、就业以后也按「本机服务上的一个工具」加，而不是做成一个大应用里的许多页面。可以是同一进程里的不同路由，或以后再拆命令。第一期只挂选刊。
